# InvestAd — Context for an LLM picking up this codebase

A handoff document describing what exists today. `docs/tech-stack.md` is the original design
doc: useful for intent, but it does not reflect implementation status.

## What this is

A country-aware investment advisory agent (final-year project, run against a real hosted
Postgres). Investors pick or have inferred a country (India / US / UK), enter holdings, get
country-parameterised portfolio analytics, and receive LLM-generated, grounded, structured
suggestions they can refine conversationally, compare across risk levels, approve, and export
to PDF. A scheduled Reflexion-style job later checks past suggestions against what happened.
All output is framed as general information, not licensed advice.

## Stack

- **Backend:** FastAPI, SQLAlchemy + Alembic (Postgres; Supabase in practice), LangGraph,
  ChromaDB (file-persisted at `chroma_db/`), yfinance + FRED + NewsAPI, APScheduler, ReportLab,
  JWT auth (python-jose, access + refresh tokens) with an in-memory login rate limiter.
- **LLMs:** Gemini + Groq behind `app/llm/router.py` (`LLMRouter.generate(prompt, PydanticSchema)`),
  with cooldown/Retry-After and automatic fallback. Every provider failure must surface as
  `ProviderError`, or fallback is bypassed. That was a real bug, now fixed and covered by
  `tests/test_llm_clients.py`. Gemini must use `response_json_schema`, not `response_schema`:
  the latter rejects dict fields on the Developer API.
- **Frontend (`frontend/`):** Vite + React 19 + TypeScript 5, Tailwind 4 + shadcn/ui-style
  components (source in `src/components/ui`), TanStack Query, Recharts, React Hook Form + Zod.
  Typed client: `src/api/schema.d.ts` is generated by openapi-typescript (`npm run gen:api`)
  and used through openapi-fetch. The Vite proxy maps `/api/*` to the backend. The Streamlit
  app was removed once the React app reached parity.
- **Tests:** pytest, about 184 tests with no network (synthetic market data in
  `tests/market_fakes.py`, mocked LLMs). Frontend correctness comes from `npm run build`
  (strict tsc).

## Country layer (`app/countries/`)

- `base.py`: `CountryConfig` (strategy-pattern config + small behaviour methods). Holds
  currency, benchmark ticker, risk-free source (FRED series + fallback; US also `^TNX`), ticker
  suffixes, exchanges, capital-gains summary (general info, "as of"), tax-advantaged accounts,
  regulatory disclaimer, and minor currency units (LSE prices come in **GBp/pence**, so divide by 100).
- `india.py` / `united_states.py` / `united_kingdom.py`, registered in `registry.py`
  (UK = `GB`, alias `UK`). A new country means one module plus one registry line.
- `inference.py` is offline and rule-based. Per holding: suffix (high), exchange (high),
  currency (medium), plain US-style ticker (US, medium), else unresolved (low). Per portfolio:
  value- or count-weighted breakdown, mixed detection, and confidence. `resolve_country`: user
  selection wins; with no portfolio (or an uninferable one) and no selection it raises
  `CountryRequiredError`.

## Analysis (`app/services/country_analysis.py`, data access in `price_data.py`)

`POST /portfolio/analyze` (auth required). Fetches 6mo–5y daily history (cached per day),
converts via yfinance FX (`{FROM}{TO}=X`) into the base currency, and computes returns,
annualised volatility, Sharpe, beta, max drawdown, HHI, and allocation by
country/sector/asset class/currency.
- **Combined view:** benchmark and risk-free rate of the base currency's country.
- **Per-country view:** each market in its own currency vs its local benchmark and rate.
- No branch on a specific country anywhere: everything reads the config.
- Profile stores optional `country` / `base_currency` overrides (migration `7c2e9a41d5b3`).

## Portfolio import (`app/services/portfolio_import.py`, `POST /portfolio/import`)

The format is sniffed from the bytes (xlsx/docx/ods are all zip files and are told apart by their
contents). Attempts run in this order:
1. **Tables** (CSV/TSV/semicolon, Excel/ODS, JSON, PDF, Word, HTML): find the header row in the
   first 25 rows and fuzzy-match column names against broker synonyms (Zerodha "Instrument/Qty./
   Avg. cost", Fidelity "Cost Basis Total", etc.). A total-cost column becomes per-unit cost.
2. **Lines** like `RELIANCE.NS 20 2400` / `NSE:TCS, 10`.
3. **AI extraction** (`method="ai"`) for screenshots/photos, scanned PDFs (pages rendered to
   images), name-only exports (Groww) and prose. Images are downscaled to 2000px JPEG, and the
   router prefers Gemini for images: Groq's `qwen/qwen3.8-27b` vision model was seen substituting
   look-alike tickers, so a fallback read adds an extra warning.

Bare tickers get `default_country`'s suffix; `NSE:`-style prefixes and exchange columns map via
`CountryConfig.exchange_suffixes`. `verify_tickers()` (route layer, network) then checks each
ticker has yfinance data. It reverts wrong guesses (`AAPL.NS` → `AAPL`), adds missing home suffixes
(`ITC` → `ITC.NS`) and flags unknown tickers with `price_found=false`. Nothing is persisted: the
UI loads results into the editable holdings table. The LLM interface takes optional
`images=[(bytes, mime)]`, and `LLMRouter.generate(..., prefer="gemini")` orders a preferred provider
first without losing fallback.

## Agent graphs (`app/agents/<name>/{state,nodes,graph}.py`)

- `advice`: analyze_portfolio → load_country_context → retrieve_market_context → generate_advice.
  Country context travels through state and is rendered generically by
  `recommendation_engine.build_advice_prompt`. Retrieval prefers ChromaDB docs tagged with the
  country.
- `market_intelligence` (6-way fan-out ingest; index docs tagged with country), `refinement`,
  `scenario` (3 parallel risk variants), `self_assessment` (Reflexion-style evaluate →
  retrieve similar past reflections → reflect; logged for human review, never auto-applied).

`POST /advice/stream` returns SSE. It emits `stage` events (started/completed per node),
`context` (resolved country/currency/source/warnings), one `section` per suggestion field plus
a disclaimer, then `done` (with the saved recommendation id) or `error`. Progressive rendering
is at stage/section granularity: the router returns validated JSON, not tokens. The frontend
uses `@microsoft/fetch-event-source`, because EventSource can't POST or send auth headers.

## Frontend auth

The access token lives in memory; the refresh token and investor id live in localStorage (a
known XSS trade-off; httpOnly cookies would need backend changes). `authFetch` adds the bearer
token and does a single-flight refresh + one retry on 401.

## Known gaps / rough edges

- Not deployed. The Supabase free tier pauses after about a week idle: restore it in the
  dashboard, then run `alembic upgrade head` if migrations are pending.
- Login rate limiter and APScheduler job are in-process (single instance only).
- ChromaDB is a local directory (not durable in containers without a volume).
- Simplifications: tax summaries are illustrative ("as of" dated); the stock/bond heuristic
  uses yfinance categories; risk-free fallbacks are static; market context beyond index docs
  (sector ETFs, FRED macro) is still US-centric; the legacy `/holdings/tax-analysis` estimate
  is US-only; analysis uses current quantities over the lookback (no cash-flow/transaction history).
- No password reset/email verification; no CI.
